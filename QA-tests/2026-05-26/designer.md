## 2. Знайдені проблеми

### D-1 🔴 Login-сторінка ігнорує `prefers-color-scheme` та збережену тему

**Severity:** 🔴 Critical (порушує DESIGN.md §1 — "Every screen must be usable on iPhone-sized viewports + light+dark always")
**Сторінка:** `/login`
**Кроки:**

1. У `/dashboard` увімкнути світлу тему (Sun/Moon у топбарі) → `localStorage.theme = "light"`.
2. Logout (або просто протух сесії — як у моєму випадку).
3. Відкрити `/login`.

**Очікувано:** сторінка зʼявляється у тій же темі, що збережена в localStorage (світла).
**Фактично:** сторінка завжди в **темній** темі (navy gradient + темна картка) — нема перемикача та нема hydration з localStorage. Користувачі з контрастним зором, у яких система світла + dyslexic-friendly preferences, отримують високий контраст білого тексту на навіть темнішому фоні (поганий початковий контакт з продуктом).

**Рекомендація:**

- У `src/app/(auth)/layout.tsx` додати такий же бутстрап-скрипт, як у `src/app/layout.tsx` (DESIGN.md §1).
- Топбар на `/login` не потрібен, але мінімум — респект до `localStorage.theme` або `(prefers-color-scheme: light)`.
- Як варіант — додати компактний sun/moon у верхньому правому куті cards.

Скрін: dark login screen ss_4058slqi4 (виявлено при переході з світлого `/dashboard` → 401 → редірект на login).

### D-2 🔴 KPI-дашборд "Прострочені завдання" розходиться зі сторінкою `/tasks`

**Severity:** 🔴 Critical (дані KPI неточні — це підриває довіру до головного екрану)
**Сторінки:** `/dashboard` ↔ `/tasks`
**Кроки:**

1. Відкрити `/dashboard` під admin.
2. Прочитати KPI **"ПРОСТРОЧЕНІ ЗАВДАННЯ: 0 / Все під контролем"**.
3. Перейти `/tasks` → у заголовку "Завдання · Всього: 1 · Виконано: 0 · **Прострочено: 1**".

**Очікувано:** числа збігаються. Дашборд KPI має показувати глобальний лічильник overdue tasks (для адміна — по всій системі), або підпис KPI має експліцитно вказувати "Мої" / "По всій системі".
**Фактично:** дашборд показує 0, реальна кількість 1. Можливо запит `dashboard.kpi.overdueTasksMine` працює по `assigneeId = me`, а `task.list` без фільтра — для адміна цей семантичний підрив не очевидний.

**Рекомендація:**

- Або привести логіку до того, що KPI = глобальний overdue count.
- Або змінити підпис на **"Мої прострочені завдання"**.
- Локація: ймовірно `src/server/routers/dashboard.ts` (метод KPI), `src/app/(app)/dashboard/page.tsx`.

Скрін: dashboard light ss_3004d2xil, tasks page ss_6501fgu21.

### D-3 🟠 Лічильник стандартів у сайдбарі розсинхронізований із дашбордом і списком

**Severity:** 🟠 High
**Сторінки:** Sidebar nav · `/dashboard` · `/standards`

**Рекомендація:** запит `dashboard.navCounts.standards` має бути узгоджений з KPI — або обидва TOTAL, або обидва ACTIVE (рекомендовано ACTIVE — користувачам цікавіше актуальне). Локація: `src/server/routers/dashboard.ts` метод `navCounts`.

**Фактично:** для кожного учасника три окремі кнопки. Активна — підкреслена іншим кольором ("Очікується" в темному фоні). Виглядає як trio of checkboxes/buttons. Багато простору.

**Очікувано:** **segmented control** — три кнопки злиті в один прямокутник з активним станом виділеним фоном/кольором (як toggle group у Radix).

**Рекомендація:** використати `RadioGroup` від Radix із кастомним стилем segmented (зразок — Apple iOS toolbars). Локація: `src/components/meetings/AttendeeRow.tsx`.

Скрін: ss_75954d1x0.

### D-17 🟡 "+12 цього місяця" — двозначна метрика

**Severity:** 🟡 Medium
**Сторінка:** `/dashboard` → KPI "АКТИВНИХ СТАНДАРТІВ 12 / +12 цього місяця"
**Фактично:** саме "**+12**" з плюсом виглядає як ΔΔ — дельта, тобто "за цей місяць додано 12". Але оскільки активних саме 12 і +12 нових — це підозріло. Можливо, метрика глобальна "усього в системі" = 12 і дельта = 12.

**Очікувано:** окремий лейбл "Цього місяця додано: 12" або, якщо це загальна кількість, без "+" перед цифрою.

**Рекомендація:** перевірити логіку у `src/server/routers/dashboard.ts` метод KPI; нагадати про правильну роль "delta" vs "total".

Скрін: ss_7712txzjx (зверху).

### D-18 ℹ️ Search input у `/standards` зберігається у localStorage між сесіями (виявлено артефакт "QA-T")

**Severity:** ℹ️ Info / Minor
**Сторінка:** `/standards`
**Фактично:** при першому відкритті у новому браузерному вікні input був заповнений "QA-T" — залишок від попередньої QA-сесії іншого автора. Тобто значення зберігається в localStorage.

**Очікувано:** локальний state для search — це OK (зручно), але краще мати кнопку "✕" в input для очищення (зараз треба ручно очищати).

**Рекомендація:** додати clear-button (X icon) на правому краю input коли value ≠ "".

Скрін: ss_8509qehq3 (видно "QA-T" в input).

### D-19 ℹ️ Cmd+K не спрацював через MCP key-press (button-click працює)

**Severity:** ℹ️ Info (не баг продукту — це обмеження мого автомейтінга)
**Опис:** на macOS Chrome через MCP `key`-action "cmd+k" не відкрило глобальний пошук. Кнопка `<GlobalSearch>` спрацювала по кліку. Можливо, Cmd+K забирає Chrome (browser bookmark search) до Webhook’а.
**Рекомендація:** убедитись що Cmd+K — це `preventDefault()` всередині `useHotkeys('cmd+k', ...)` хука. Якщо не блокувати — Chrome ловить його у свій search.

### D-20 ℹ️ Mobile QA не вдалось зробити повноцінно

**Severity:** ℹ️ Info (обмеження середовища)
**Опис:** resize_window у Chrome-MCP знижував `window.outerWidth` до 400, але `window.innerWidth` лишався 1512 (devicePixelRatio = 2). Тобто DOM-візуально продовжував рендеритись у desktop-layout.

**Що варто перевірити вручну/у DevTools-emulation:**

- `/login` форма на 375px ширини — центрована, не лишається горизонтальний scroll.
- Сайдбар на `<lg` — drawer behind hamburger (DESIGN.md §2).
- Таблиця стандартів на 640px — горизонтальний scroll (`overflow-x-auto`) працює.
- KPI-картки на дашборді складаються в 1 колонку.
- Modal `+ Завдання` / `+ Документ` — bottom-sheet docking.
