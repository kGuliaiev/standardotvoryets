# Задачі проєкту «Стандартотворець»

Єдиний список **усіх** задач — і запланованих, і виконаних (комітиться в
репозиторій, доступний усім розробникам). Кожна задача має **інкрементний
номер** — посилайся на нього, напр. «реалізуй #1» або «реалізуй #1, #3».

**Статуси:** `[ ]` заплановано · `[~]` в роботі · `[x]` виконано
**Як наповнюється:** кожна поставлена задача додається сюди; виконані **не
видаляються**, лише позначаються `[x]` — щоб історія лишалась повною й її можна
було переглянути будь-коли. Формулювання — не дослівні цитати, а опис,
достатній для реалізації (модуль, місце, що саме зробити).

## Беклог (активні + останні)

### #1 — Хлібні крихти картки завдання ведуть на стандарт

`[x]` виконано · модуль: **Завдання** (`/tasks/[id]`, `TaskDetail`)

Угорі сторінки завдання breadcrumb має містити **клікабельне посилання на
стандарт**, до якого належить завдання (`task.standard` →
`/standards/<standardId>`, показати код + назву стандарту), щоб з картки
завдання можна було повернутись на стандарт, з якого прийшов.

### #2 — Іконка «i» з описом у рядку завдання

`[x]` виконано (2026-08-04) · модуль: **Завдання** (усі списки із рядком завдання)

Якщо у завдання заповнено `description`, **після назви завдання** показувати
іконку «i»; при наведенні — спливна підказка/модалка з повним текстом опису.

Місця, де відображається рядок завдання:

- глобальний список `/tasks` — `TaskRowItem`;
- вкладка «Завдання» стандарту — `StandardTaskRow`;
- дашборд «Мої завдання» (якщо там показується рядок завдання).

**Як зроблено:** `src/components/ui/DescriptionNote.tsx` — `InfoToggle` (кнопка (i),
рендериться тільки коли `description` непорожній) + `DescriptionNote` (панель).
Розкриття **inline під рядком**, не спливна підказка: картки списків мають
`overflow-hidden`, плаваюча панель обрізалась би. Іконка стоїть у спільному
`flex-1 min-w-0` контейнері з назвою, тож тримається впритул до тексту, а не біля
правого краю. Застосовано для задач **і** підзадач у `/tasks` та у вкладці
«Завдання» стандарту; у картці задачі (i) відкриває наявну панель деталей.

### #3 — Інлайновий прямий редактор тіла документа + право в матриці

`[x]` виконано · модуль: **Стандарти → текст документа** (`StandardBodyEditor`, `rbac`)

Замість модалки «Редагувати все» — **завжди-увімкнений WYSIWYG**, що
показується одразу при відкритті тексту документа (для користувачів із
правом прямого редагування). Панель форматування **винести й пришпилити
окремо до верху** (sticky, поза карткою тексту).

- Нове право в матриці ролей, напр. `standard:editBody` — тогл «Редагувати
  текст документа» (хто може правити **напряму, без підтвердження**).
  За замовч.: керівник / заступник / секретар (як `editMeta`).
- Користувачі **без** права — read-only + потік пропозицій (як зараз).
- Збереження — **автозбереження** з debounce (~1.2 с) + flush при
  розмонтуванні (мутація `suggestion.updateBody`), без голосування. Кнопки
  «Зберегти» немає. (Рішення користувача: автозбереження замість кнопки.)
- Не ламати наявний потік пропозицій/inline-коментарів для тих, хто без права.
- Кнопку «Редагувати все» прибрано (інлайновий редактор її замінює).

**Реалізовано:** нове право `standard:editBody` (дефолт = керівник/заступник/
секретар) в `ALL_ACTIONS`/`ACTION_LABELS`/`PERMISSIONS`; серверні мутації
`suggestion.updateBody`/`replaceBody`/`accept`/`reject` та маршрут
`import-body` тепер на `standard:editBody`.

Підсумковий UX — **3 режими** (перемикач угорі):

- **Перегляд** — лише читання тексту (без кнопок пропозицій/прийняття).
- **Пропозиції** — read-only-стаття з кнопками пропозицій + inline-коментарі
  (через виділення тексту — overlay працює тільки на read-only-статті, тому
  коментарі живуть тут, а не в редакторі) + прийняття/відхилення пропозицій
  для носіїв `editBody`.
- **Редагування** — завжди-увімкнений `InlineBodyEditor` (sticky-панель угорі,
  автозбереження); праворуч той самий блок «Зміни / Коментарі».

Доступність: «Перегляд» — усім; «Пропозиції» — у кого `comment:add`;
«Редагування» — лише `standard:editBody`. Дефолт: editBody → Редагування,
інакше → Пропозиції / Перегляд.

### #4 — Не приймалась пропозиція в документах із таблицями (конфлікт)

`[x]` виконано · модуль: **Стандарти → пропозиції** (`suggestion.accept`,
`splitParagraphs`, `splitHtmlBlocks`)

При прийнятті пропозиції видавало «Оригінальний текст параграфа №N вже не
знайдено», хоча ніхто нічого не міняв. Причина: серверний `splitParagraphs`
рахував глибину вкладеності лише для `br/img/hr`, а TipTap-таблиці містять
порожній елемент `<col>` (void, без закриття) → глибина не поверталась до 0,
і весь текст після першої таблиці злипався в один блок, через що індекси
параграфів «з'їжджали». Виправлено: усі HTML void-елементи
(`area,base,br,col,embed,hr,img,input,link,meta,param,source,track,wbr`) тепер
не збільшують глибину — і на сервері, і в SSR-фолбеку клієнта.

### #5 — Модалка підтвердження прийняття пропозиції (з дифом)

`[x]` виконано · модуль: **Стандарти → пропозиції** (`StandardBodyEditor`)

Перед застосуванням пропозиції показується модалка `AcceptPreviewModal` з
типом операції, автором, **дифом** (що саме зміниться — word-level для заміни,
зелений блок для додавання, червоний закреслений для видалення) та
обґрунтуванням. Підтвердження — «Прийняти зміну». Диф винесено в спільний
`SuggestionDiff` (картка + модалка).

### #6 — «Почати з нуля» відкривало стару модалку замість інлайн-редактора

`[x]` виконано · модуль: **Стандарти → текст документа** (`StandardBodyEditor`)

Для порожнього документа кнопка «Почати з нуля» відкривала легасі-модалку
`BulkEditModal` («Редагувати текст документа» з кнопкою «Зберегти») — інший
редактор, ніж новий інлайновий з 3 режимами. Виправлено: «Почати з нуля» тепер
створює порожнє тіло (`<p></p>`) через `updateBody`, після чого відкривається
звичайний інлайновий редактор (режим «Редагування»). Легасі-модалку
`BulkEditModal` повністю прибрано — тепер один редактор на всі сценарії.

### #7 — Поле вводу коментаря вилітало за край вікна на коротких рядках

`[x]` виконано · модуль: **Стандарти → inline-коментарі** (`InlineComments`)

Плаваюче поле вводу коментаря (та «таблетка» Коментувати/Правка) центрувалось
по виділенню (`translateX(-50%)`), але обмежувалось лише справа — на короткому
рядку біля лівого краю лівий край блоку йшов за межі вікна. Виправлено: центр
позиціонування **клампиться з обох боків** з урахуванням половини ширини блоку
(composer 320px → ±168px; таблетка → ±128px), тож воно не вилазить за жоден край.

### #8 — Дефолтний шрифт Times New Roman 14pt у редакторі тіла

`[x]` виконано · модуль: **Стандарти → редактор** (`RichTextEditor`, `StandardBodyEditor`)

При відкритті тексту (особливо порожнього/нового) дропдауни показують
«— шрифт —» і «—». Має бути **дефолт: Times New Roman, 14pt** — і візуально в
тулбарі, і фактично для нового тексту. Узгодити з базовим шрифтом тіла
(Times New Roman вже стоїть як CSS-дефолт — синхронізувати значення тулбара).

### #9 — Показувати актуальний розмір/шрифт при виділенні

`[x]` виконано · модуль: **Стандарти → редактор** (`RichTextEditor` Toolbar)

При виділенні тексту дропдауни розміру та шрифту мають відображати **фактичні
значення** виділеного фрагмента (зараз «—»). Зчитувати з
`editor.getAttributes('textStyle').fontSize/fontFamily`; якщо порожньо —
показувати дефолт (14pt / Times New Roman), а не прочерк.

### #10 — Висота блоку редактора = висота правої рейки

`[x]` виконано · модуль: **Стандарти → редактор** (`StandardBodyEditor` edit layout)

Картка редактора зліва має тягнутись на **висоту правого блоку
«Зміни / Коментарі»** (рівні висоти колонок), а не бути коротшою. Зараз editor
має фіксований `min-h`, рейка — свій. Вирівняти (напр. `items-stretch` + спільна
висота, або editor росте до висоти рейки).

### #11 — Фокус по кліку в будь-якому місці поля тексту

`[x]` виконано · модуль: **Стандарти → редактор** (`RichTextEditor`)

Зараз курсор ставиться лише в межах висоти введеного тексту; клік у порожню
область нижче не фокусує редактор. Потрібно: **клік у будь-якому місці області
тексту ставить фокус** (курсор у кінець), тобто вся min-height-область
редактора клікабельна для фокуса, а не лише рядки з текстом.

### #12 — Підзадачі до завдання

`[x]` виконано (2026-07-14) · модуль: **Завдання** · ADR-0007

Модель `TaskChecklistItem` — один рівень вкладеності, поля як у задачі
(`title` / `description` / `isDone` / `dueDate` / `assigneeId` / `order`), каскад від
`Task`. Процедури `task.checklistAdd/Toggle/Update/Delete/Reorder`. Свідомо **не**
`Task.parentId`: без статус-машини, пріоритету й власного аудиту, не враховується
в KPI дашборда (інакше одна задача з 24 кроками переважила б решту).

### #13 — Drag-and-drop порядку підзадач

`[x]` виконано (2026-08-03) · модуль: **Завдання** (`TaskDetail`)

`@dnd-kit/core` + `@dnd-kit/sortable`. Тягнути можна лише за ручку `GripVertical` —
чекбокс, назва й кнопки лишаються клікабельними. `PointerSensor` з порогом 4px,
щоб звичайний клік не рахувався перетягуванням.

### #14 — Розгортання підзадач просто в списку

`[x]` виконано (2026-07-14) · модуль: **Завдання** (`/tasks`, вкладка стандарту)

Шеврон біля чипсика `☑ 2/5` розкриває підзадачі в рядку, без переходу в картку.
Стан розгорнутості — per-user у localStorage (`useExpandedTasks`, ключ
`standartotvorets.expandedTaskIds.v1`) + кнопки «Розгорнути все / Згорнути все».

### #15 — Шаблони задач

`[x]` виконано (2026-08-03) · модуль: **Завдання + Стандарти** · ADR-0008

`Standard.isTaskTemplate` + `standard.templates` + `task.copyFromTemplate`
(режими `append` / `replace`). Дедлайни **перераховуються**: зсув у днях від
найближчого етапу джерела → той самий зсув від відповідного етапу цілі.
Виконавці скидаються. UI — модалка «Створити з шаблону». Разовий прогін по всіх
стандартах виконано на проді 2026-08-03.

### #16 — Дерево в списку завдань

`[x]` виконано (2026-08-03) · модуль: **Завдання** (`/tasks`)

Групування РГ → Стандарт із заголовками-посиланнями замість суцільного списку за
датою. Перемикач «Дерево / Список», режим у localStorage (`tasks.viewMode.v1`).
Для області «один стандарт» лишається плоский список — ієрархія там зайва.

### #17 — Власний скрол списку завдань

`[x]` виконано (2026-08-06) · модуль: **Завдання** (`/tasks`)

На lg+ сторінка займає висоту вікна; гортається лише перелік завдань і дерево РГ,
шапка з фільтрами лишається на місці. Нижче lg — звичайний потік сторінки.

### #18 — Метадані Програми стандартизації

`[x]` виконано (2026-07-14) · модуль: **Стандарти**

`partProgram` / `programNumber` / `indeks` / `oldTitle` — у формі створення,
модалці редагування й списку `/standards`. Чипсик завдання показує реальний
індекс-гриф (`СТД-100-200-001-2026-В`) замість внутрішнього коду, з fallback на `code`.

### #19 — Редаговані терміни етапів

`[x]` виконано (2026-07-14) · модуль: **Стандарти** (`StandardDetail`)

Кнопка «Терміни» в шапці степера відкриває модалку з п'ятьма датами поетапного
плану. Раніше їх можна було задати лише при створенні стандарту.

### #20 — Enter як головна дія у формах

`[x]` виконано (2026-08-03) · модуль: **наскрізно**

Тіла модалок загорнуто у `<form onSubmit>`, головна кнопка стала `type="submit"`:
`TaskFormModal`, `DocumentUploadModal`, `DocumentEditMetaModal`,
`TaskCopyFromTemplateModal`, «Редагувати стандарт» і «Терміни етапів» у
`StandardDetail`. У textarea Enter лишає новий рядок.

## Виконано раніше (до запровадження нумерованого беклогу)

Дрібні правки зведено в один пункт. Усі — `[x]` виконано.

### Засідання / Протоколи

- [x] AI-генерація чернетки протоколу: кнопка + промпт під формальний стиль.
- [x] Авто-приховування AI-панелі та автозбереження одразу після генерації.
- [x] Запит «замінити чи додати», коли пункти порядку денного вже існують.
- [x] Вибір доповідача/відповідального зі списку всіх учасників + вільний

- [x] Компактніша («2-рядкова») шапка картки засідання.

### Експорт (Word / PDF)

- [x] Збереження стилів Word при імпорт → редагування → експорт (розміри
      тексту, вирівнювання, таблиці, посилання).
- [x] Word-експорт: пункти порядку денного фільтруються за секцією (не

- [x] У /protocols «РГ №X» і «№ 3/4/2026» не переносяться на два рядки.

### Права / RBAC / стабільність сесії

- [x] Окреме право в матриці на AI-генерацію протоколу (`meeting:generateAiDraft`).
- [x] Пункт «Сповіщення» доданий у матрицю меню + перевірка за роллю; винесений
      із розділу «Адмін» (доступний усім за правами).
- [x] Налаштування видимі адміну та керівнику центру.
- [x] Права керівника РГ і керівника центру (DIRECTOR) тепер **об’єднуються**
      (union), а не беруться максимум одного.
- [x] Виправлено відображення прав секретаря в матриці.
- [x] DIRECTOR бачить документи / коментарі / протоколи в усіх РГ.
- [x] Керівник центру може керувати протоколом за грантом у матриці — клієнтський
      `can()` тепер враховує DB-overrides (`permission.myOverrides` +
      `PermissionsBootstrap`).
- [x] Виправлено зникнення прав адміна в Chrome (кеш у JWT,
      `refetchOnWindowFocus={false}`, оновлення `globalRole` у session callback).
- [x] Сід більше не скидає роль директора при кожному редеплої (guard за
      наявністю даних).
- [x] Меню більше не «блимає» повним списком перед звуженням під роль.
- [x] Текст сповіщення про коментар: «Адміністратор написав…» замість підстановки
      чужого імені.
