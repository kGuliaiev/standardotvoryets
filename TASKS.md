# Задачі проєкту «Стандартотворець»

Єдиний список **усіх** задач — і запланованих, і виконаних (комітиться в
репозиторій, доступний усім розробникам). Кожна задача має **інкрементний
номер** — посилайся на нього, напр. «реалізуй #1» або «реалізуй #1, #3».

**Статуси:** `[ ]` заплановано · `[~]` в роботі · `[x]` виконано
**Як наповнюється:** кожна поставлена задача додається сюди; виконані **не
видаляються**, лише позначаються `[x]` — щоб історія лишалась повною й її можна
було переглянути будь-коли. Формулювання — не дослівні цитати, а опис,
достатній для реалізації (модуль, місце, що саме зробити).

## Беклог (активні + останні)

### #1 — Хлібні крихти картки завдання ведуть на стандарт

`[ ]` заплановано · модуль: **Завдання** (`/tasks/[id]`, `TaskDetail`)

Угорі сторінки завдання breadcrumb має містити **клікабельне посилання на
стандарт**, до якого належить завдання (`task.standard` →
`/standards/<standardId>`, показати код + назву стандарту), щоб з картки
завдання можна було повернутись на стандарт, з якого прийшов.

### #2 — Іконка «i» з описом у рядку завдання

`[ ]` заплановано · модуль: **Завдання** (усі списки із рядком завдання)

Якщо у завдання заповнено `description`, **після назви завдання** показувати
іконку «i»; при наведенні — спливна підказка/модалка з повним текстом опису.

Місця, де відображається рядок завдання:

- глобальний список `/tasks` — `TaskRowItem`;
- вкладка «Завдання» стандарту — `StandardTaskRow`;
- дашборд «Мої завдання» (якщо там показується рядок завдання).

> Уточнення: застосувати в усіх трьох місцях чи лише в якомусь конкретному?

### #3 — Інлайновий прямий редактор тіла документа + право в матриці

`[x]` виконано · модуль: **Стандарти → текст документа** (`StandardBodyEditor`, `rbac`)

Замість модалки «Редагувати все» — **завжди-увімкнений WYSIWYG**, що
показується одразу при відкритті тексту документа (для користувачів із
правом прямого редагування). Панель форматування **винести й пришпилити
окремо до верху** (sticky, поза карткою тексту).

- Нове право в матриці ролей, напр. `standard:editBody` — тогл «Редагувати
  текст документа» (хто може правити **напряму, без підтвердження**).
  За замовч.: керівник / заступник / секретар (як `editMeta`).
- Користувачі **без** права — read-only + потік пропозицій (як зараз).
- Збереження — **автозбереження** з debounce (~1.2 с) + flush при
  розмонтуванні (мутація `suggestion.updateBody`), без голосування. Кнопки
  «Зберегти» немає. (Рішення користувача: автозбереження замість кнопки.)
- Не ламати наявний потік пропозицій/inline-коментарів для тих, хто без права.
- Кнопку «Редагувати все» прибрано (інлайновий редактор її замінює).

**Реалізовано:** нове право `standard:editBody` (дефолт = керівник/заступник/
секретар) в `ALL_ACTIONS`/`ACTION_LABELS`/`PERMISSIONS`; серверні мутації
`suggestion.updateBody`/`replaceBody`/`accept`/`reject` та маршрут
`import-body` тепер на `standard:editBody`.

Підсумковий UX — **3 режими** (перемикач угорі):

- **Перегляд** — лише читання тексту (без кнопок пропозицій/прийняття).
- **Пропозиції** — read-only-стаття з кнопками пропозицій + inline-коментарі
  (через виділення тексту — overlay працює тільки на read-only-статті, тому
  коментарі живуть тут, а не в редакторі) + прийняття/відхилення пропозицій
  для носіїв `editBody`.
- **Редагування** — завжди-увімкнений `InlineBodyEditor` (sticky-панель угорі,
  автозбереження); праворуч той самий блок «Зміни / Коментарі».

Доступність: «Перегляд» — усім; «Пропозиції» — у кого `comment:add`;
«Редагування» — лише `standard:editBody`. Дефолт: editBody → Редагування,
інакше → Пропозиції / Перегляд.

### #4 — Не приймалась пропозиція в документах із таблицями (конфлікт)

`[x]` виконано · модуль: **Стандарти → пропозиції** (`suggestion.accept`,
`splitParagraphs`, `splitHtmlBlocks`)

При прийнятті пропозиції видавало «Оригінальний текст параграфа №N вже не
знайдено», хоча ніхто нічого не міняв. Причина: серверний `splitParagraphs`
рахував глибину вкладеності лише для `br/img/hr`, а TipTap-таблиці містять
порожній елемент `<col>` (void, без закриття) → глибина не поверталась до 0,
і весь текст після першої таблиці злипався в один блок, через що індекси
параграфів «з'їжджали». Виправлено: усі HTML void-елементи
(`area,base,br,col,embed,hr,img,input,link,meta,param,source,track,wbr`) тепер
не збільшують глибину — і на сервері, і в SSR-фолбеку клієнта.

### #5 — Модалка підтвердження прийняття пропозиції (з дифом)

`[x]` виконано · модуль: **Стандарти → пропозиції** (`StandardBodyEditor`)

Перед застосуванням пропозиції показується модалка `AcceptPreviewModal` з
типом операції, автором, **дифом** (що саме зміниться — word-level для заміни,
зелений блок для додавання, червоний закреслений для видалення) та
обґрунтуванням. Підтвердження — «Прийняти зміну». Диф винесено в спільний
`SuggestionDiff` (картка + модалка).

### #6 — «Почати з нуля» відкривало стару модалку замість інлайн-редактора

`[x]` виконано · модуль: **Стандарти → текст документа** (`StandardBodyEditor`)

Для порожнього документа кнопка «Почати з нуля» відкривала легасі-модалку
`BulkEditModal` («Редагувати текст документа» з кнопкою «Зберегти») — інший
редактор, ніж новий інлайновий з 3 режимами. Виправлено: «Почати з нуля» тепер
створює порожнє тіло (`<p></p>`) через `updateBody`, після чого відкривається
звичайний інлайновий редактор (режим «Редагування»). Легасі-модалку
`BulkEditModal` повністю прибрано — тепер один редактор на всі сценарії.

### #7 — Поле вводу коментаря вилітало за край вікна на коротких рядках

`[x]` виконано · модуль: **Стандарти → inline-коментарі** (`InlineComments`)

Плаваюче поле вводу коментаря (та «таблетка» Коментувати/Правка) центрувалось
по виділенню (`translateX(-50%)`), але обмежувалось лише справа — на короткому
рядку біля лівого краю лівий край блоку йшов за межі вікна. Виправлено: центр
позиціонування **клампиться з обох боків** з урахуванням половини ширини блоку
(composer 320px → ±168px; таблетка → ±128px), тож воно не вилазить за жоден край.
